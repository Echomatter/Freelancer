# Echoflex dialogs

`src/echoflex/Dialog.tsx` owns all app-shading popups. It supplies the compact header, scrollable content, fixed wrapping action footer, palette tokens, rounded border, backdrop, accessible title, keyboard containment and focus return. Use `size="compact"`, `"standard"` or `"wide"`; `layout="stack"` or `"split"` selects a content layout. Split content stacks automatically in narrow windows. Dynamic content belongs in `children`; specialized choice cards, Git previews and forms remain custom content. `onSubmit` makes the shared frame a form. No component needs to create its own modal shell.

`ConfirmDialog` standardizes simple confirmations. `useConfirmation` provides an asynchronous replacement for browser confirmation boxes. Questions and permissions share the same Dialog shell and preserve native answer/reply shapes. Escape means Later for native requests, never Deny or consent. Failed replies remain open with their inputs and an error; in-flight replies cannot be submitted twice. There is no backdrop-click dismissal.

The stack shows one native top-layer dialog at a time, in priority order: subagent requests, chat decisions, confirmations, ordinary dialogs. Covered dialogs remain mounted; focus and drafts return when the covering request is answered or deferred. A newly opened ordinary dialog cannot cover a subagent request. Parent and worker question state is retained separately. Native session identity and bounded ancestry determine which descendant requests belong to the open conversation; unrelated sessions and other project directories are excluded. Response authorization still uses the existing native permission path.

Migrated flows: Queue/Delegate (clarification), questions, chat/configuration permissions, model-rating picker, provider connection, project open/manage/loading, project removal, draft replacement, Git review/setup, conversation/project archive, and SQLite compaction. Anchored nonmodal disclosures such as the project picker, usage popup and action menus remain purpose-built; they do not shade or make the app inert. Agent/workflow editors remain inline pages.

`npm run build` runs `scripts/check-echoflex.mjs` before TypeScript and Vite. It rejects new raw dialog markup, custom modal roles, browser confirmation/alert/prompt calls, independent `showModal` calls, feature-owned backdrops and competing dialog shell styles. `npm run check:echoflex` runs the boundary check alone. Add feature styles to body content, not the shell. New exceptions require an explicit documented architectural reason.

The UI/runtime contract is version 10; restart the local server after rebuilding. Validation covers verified descendant scoping and guardrails in `tests/echoflex-dialogs.test.mjs`, plus production browser stacking, focus, errors, drafts, layout and native response behavior in `tests/dialogs.browser.mjs`. Fixtures simulate provider execution; they do not prove inference or grant real permissions.
