# Model ratings update contract

The native OpenCode provider inventory supplies the list of runnable model IDs and technical limits. The backend routing evidence (`backend/routing/model-evidence.json`) continues to own selection policy and its independently reviewed source/benchmark claims. The per-user `model_catalog` in `freelancer.sqlite` stores a complete public presentation snapshot for each discovered model plus separately estimated card ratings; it does not store native authentication or replace the route selector. A newly discovered model is **Missing information** until its estimate is accepted. **Updated** means the estimate is filled, not that a benchmark has been scientifically verified or the route is usable.

**Update Model Ratings** stays on Models and opens a small picker for the configuration model and optional model-supported Intelligence. **Go** closes the picker and runs behind the shared Echoflex progress bar, with text inside. It researches all missing profiles in batches of six; if none are missing, it refreshes all discovered profiles. One job may run at a time. Each batch has a durable native message identity and captured Researcher/Explore definitions. The server observes OpenCode independently of the browser and resumes after restart without resending an uncertain request. Valid profiles survive partial responses and later failures. The job does not change the selected chat or model and does not rewrite routing evidence, quotas, or prices.

The bar reports one status line, then **Done** or the number of models still missing details. **Stop** aborts and verifies native execution; completed ratings remain saved. Dismissing a running bar hides presentation only, and the Models action reveals it again. **OK** or dismissing a terminal result archives the conversation in Freelancer and clears the status durably. **Retry** archives that result and researches only unresolved profiles with the same model and Intelligence. Configuration sessions are identified by durable job records, hidden from normal chat lists, all History scopes, and chat search from creation onward; they remain in native OpenCode. There is no chat panel or Open task link. Native permissions and questions remain explicit decisions when needed, never silently approved.

The natural-language research prompt asks the configuration model to identify public names, hosted aliases and model families, follow model cards, release reports and benchmark leads, and try alternate sources when pages fail. Exact provider-qualified IDs are required in the saved JSON, not in every source's public model name:

```json
{"models":[{"id":"provider/model-version","scores":{"coding":75,"reasoning":72,"research":70,"tool_use":80,"instruction_following":78},"confidence":"low","summary":"Estimated from adjacent version; no direct evaluation found.","sources":["https://provider.example/models"]}]}
```

Scores are comparative estimates on 0–100, not observed pass rates. All five score fields and an explanation are required per accepted profile. Where direct measurements do not exist, make a reasoned estimate and lower confidence; do not invent benchmark measurements, visited URLs, or provider specifications. `sources` contains only HTTPS URLs actually consulted. Empty sources are accepted as **inferred estimate**. The parser tolerates surrounding prose or JSON fences, saves complete valid profiles from partial responses, and rejects unrelated or duplicate IDs. Invalid or omitted profiles are counted as unresolved; existing ratings are preserved.

Start with primary documentation: [OpenAI model catalog](https://platform.openai.com/docs/models), [Anthropic model overview](https://platform.claude.com/docs/en/models/overview), and [Gemini models](https://ai.google.dev/gemini-api/docs/models). Benchmark starting points include [Artificial Analysis](https://artificialanalysis.ai/evaluations/artificial-analysis-intelligence-index), [Arena](https://arena.ai/leaderboard), and [SWE-bench](https://www.swebench.com/). Explain version matching and evaluation-setting differences. Use native inventory as the authority for actual availability. These links are research leads, not proof for every model.
