# Warehouse completion audit

**Audit baseline:** commit `b255fca` (`Checkpoint unified warehouse implementation for integration`), inspected through `git show` while the integration checkout was in a paused rebase. This document describes that immutable code snapshot, not the conflicted working tree or the eventual rebased result.

**Method and limits:** static inspection of the two specification documents, goal objective, source, and existing test definitions in that commit. No tests were run for this audit. Where a test is cited, it identifies fixture intent and scope; it is not a claim that the test passed in this audit or proves a Windows launch, native provider authentication, real retrieval quality, or production data state.

## Status key

- **Verified** — the checkpoint has an explicit contract/fixture that exercises the stated behavior. Test execution is not asserted here.
- **Implemented** — source exists, but the cited evidence does not establish the complete acceptance behavior.
- **Incomplete** — an identified acceptance gap remains in source or test coverage.
- **Superseded** — the refreshed goal excludes this prior-user-data import/cutover work. Import utilities remain explicit maintenance features and are not first-run behavior.

The refreshed goal requires fresh `workspace-v2`, preserves OpenCode’s native configuration/data/credentials, excludes prior Freelancer data import and cutover, and requires durable pin-capture jobs, in-place derived-index repair, asynchronous analytical reads, persisted indexing jobs, and a requirement-by-requirement audit. The checkpoint still names `workspace-v1` in `server/runtime-config.mjs` and in `docs/storage-consumer-inventory.md`; that namespace mismatch is a blocking integration gap.

## Prior-user-data migration requirements superseded

The refreshed goal supersedes the specifications’ source discovery and migration/cutover steps for existing user data. These are not acceptance blockers for fresh install and must not be run as part of bootstrap:

- Do not scan, back up, import, or reconcile an existing installation’s `records.sqlite`, prior `freelancer.sqlite`, standalone `.state/*.json`, old settings profiles, pins, or Memory JSONL.
- Do not run `scripts/migrate-runtime-records.mjs`, `scripts/migration-source-backup.mjs`, `migrateLegacyPinsBatch()`, or stopped-runtime cutover procedures against prior data as goal work.
- Do keep the importer code out of startup paths and keep import opt-in/maintenance-only if retained. Explicit backup/restore of a user-selected **new workspace-v2** bundle remains in scope.
- The donor map’s migration-count/hash/cutover interruption cases are **Superseded**. New-workspace startup, schema upgrades of the newly created database, explicit selected-bundle restore, settings/database pairing, and post-restore no-replay are still applicable.

## Prioritized remaining work

1. **Unify startup on `workspace-v2` and prove fresh lifecycle.** Update the shared resolver and every consumer/inventory/test as one change. Acceptance requires disposable real-server and Windows-launcher start, restart, shutdown, native OpenCode config readback, and proving previous stores are untouched. Do not use user runtime paths.
2. **Persist pin capture jobs.** Make the pin acknowledgement transactional/prompt; store a durable capture job with exact project/session/source identity, requested revision, boundary, status/error/cancel/retry state. Capture from OpenCode API asynchronously after the pin is saved; publish immutable memory/source revision only after safe capture. Add UI for partial/missing source, progress, retry, and refresh-created revision. Current metadata-only pins are placeholders, not completion.
3. **Persist index jobs/checkpoints.** Move `server/index-jobs.mjs` process-local status to database job/run/cursor/failure records. Resume safely after restart, keep cancellation and job identity stable, commit capture/index output before advancing coverage, and test that stopped/partial work preserves the last good search copy.
4. **Make derived-index repair truly in place.** Separate FTS/projection rebuild from database recovery and explicit destructive reset. Current durable-table-copy plus database swap is not the required in-place operation. Test repair with memories, pins, evidence revisions and uncertain operational rows, and inject failure mid-rebuild.
5. **Move analytical SQL to cancellable worker isolation.** Preserve named binds, authorizer/readonly enforcement, result caps and timeout while allowing an abort during an executing query and keeping send/draft writes responsive. Test actual in-flight cancellation and lock/latency interaction, not only an already-aborted signal.
6. **Finish memory semantics and UI.** Add relation validity/supersession, distinct archive/source deletion semantics, and Files/Conversations/Memories/Facts/Pinned Memory surfaces with separate retained-evidence and live-source actions. Do not import old Memory or pins.
7. **Complete query/JEV evidence flows.** One shared contract must resolve registry project IDs and support global/optional project/model filtering identically through UI/native/CLI, including Unicode/literal filters/order/bounds/coverage. Add a bounded packet builder and broad retrieval evaluation (exact IDs, paraphrases, contradictions, history, pinned snapshots, missing source, multi-project); preserve no-JEV fallback and prove provider failure cannot block ordinary search.
8. **Close backup and SQLite evidence gaps.** Bundle selected workspace database plus matching settings revision and any retained managed artifacts; validate references, pin/memory counts and uncertain operation counts; restore only on explicit selection to a new destination and prove no dispatch replay. Record Node/Bun embedded SQLite versions and required driver facilities.
